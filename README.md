# 预算分单元 · 逐小时回放

一天的预算先拆给多个投放单元（保底 → 权重 → 上限），再按小时回放实际能花掉多少。
前端同时跑两套方案——**等权重** 与 **自定义权重**——两边共用同一份每小时流量与单价，
因此支出差异只来自分配。

技术栈：FastAPI + SQLite（后端，纯整数分计算）· React + TypeScript + Vite（前端）。

## 目录

```
backend/
  app/engine.py     预算拆分 + 逐小时回放（无框架依赖，可直接单测）
  app/samples.py    五个样例：均匀流量 / 上午集中 / 无流量 / 中途暂停 / 预算明细演示
  app/db.py         SQLite 持久化（每次回放保存一份方案快照）
  app/main.py       FastAPI 接口
  tests/            引擎与接口测试（30 个）
frontend/
  src/components/   配置栏、24 小时流量编辑、对比面板、图表、逐小时明细
  src/sim.ts        前端工具与配色顺序
```

## 运行

后端（Python ≥ 3.10）：

```bash
python3 -m venv .venv
./.venv/bin/pip install -r backend/requirements.txt
cd backend && ../.venv/bin/python -m uvicorn app.main:app --port 8000 --reload
```

前端（Node ≥ 20）：

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173，/api 代理到 http://127.0.0.1:8000
```

代理目标可用 `API_ORIGIN` 覆盖：

```bash
API_ORIGIN=http://127.0.0.1:8090 npm run dev
```

其它配置：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `PACING_DB` | SQLite 文件路径 | `backend/data/pacing.db` |

构建与测试：

```bash
cd backend && ../.venv/bin/python -m pytest tests -q
cd frontend && npm run build
```

## 计算规则

金额与曝光单价全部为**整数分**；前端以元输入（支持两位小数），提交时转分。

### 日预算拆分（`engine.plan_day`）

1. 按配置顺序用整数分满足各单元**保底**；保底先受本单元上限约束。
2. 剩余预算按**非负权重**比例分配：先取整数地板值，剩下不足整分的尾差按小数余数
   从大到小逐个 +1 分；余数相同时按**固定单元编号升序**（与配置顺序无关）。
3. 分配额达到**每日上限**的单元退出后续分配，超出的部分退回池中，在下一轮继续分；
   重复至多 `单元数 + 1` 轮即可收敛。
4. 没有正权重单元、或所有单元都已触顶时，分不出去的余额记入**全局未分配金额**。
5. 以下配置在回放前报错（HTTP 422，中文说明）：单元为空/编号重复、总预算非正、
   保底或上限为负、权重为负或非有限、可投时段非法、**保底 > 本单元上限**、
   **保底总和 > 总预算**。

### 逐小时回放（`engine.simulate_plan`）

- 每单元日预算均分到可投小时：`base, extra = divmod(budget, hours)`，多出的 `extra`
  分依次给**时间靠前**的小时。
- 当前小时没花完的余额滚入该单元**下一个可投小时**；不可提前支取后面的切片。
- 一次曝光按整数购买：`min(该小时剩余流量, 可花金额 // 单价)`；支出 = 次数 × 单价，
  永不超出可用预算或当时流量。
- 同小时多个单元共享流量，按**固定单元编号升序**先买。
- 只使用当前小时的数据：未来小时的流量/价格不会改写过去的结果。
- 暂停在**申请小时的下一小时**起生效，直到恢复小时（恢复小时必须晚于生效小时）；
  暂停小时的预算全额继续向后滚。
- 日终 `当日未花余额 = 当日预算 - 当日支出`（包含全局未分配金额）；默认每天清零，
  开启结转时并入次日总预算。
- 多日回放复用同一份 24 小时流量/单价画像（`days = 1..90`）。

### 样例

| 样例 | 用途 |
| --- | --- |
| 均匀流量 | 基线：每小时 2,000 次曝光 |
| 上午集中 | 6–12 点流量高峰，检验保底与权重对支出节奏的影响 |
| 无流量 | 全天空流量，预算全部未花，图表为 0 基线 |
| 中途暂停 | 混合流量画像 + B 单元 8 点申请暂停（9–12 点暂停，12 点恢复后集中释放滚存预算） |
| 预算明细演示 | 混合流量，适合逐小时展开查看预算来源、购买次数与余款去向 |

## 页面

- **双方案对比**：两个方案共享设置，并排展示当日 KPI、每小时支出曲线、单元分配表和
  逐小时明细；两天以上可用日切换器（两边同步切换同一天）。
- **每小时流量与单价**：24 行可编辑表格，或一次粘贴 24 行 `曝光 单价`（空格/逗号/制表符）。
- **规则说明**：上述拆分与回放规则的页面版。
- 每小时明细可展开，显示：`小时切片 + 上小时滚入 = 本小时可花`、按单价买了多少次、
  花了多少、余款滚到哪里；暂停/不可投小时标出状态。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| GET | `/api/samples` | 样例摘要 |
| GET | `/api/samples/{key}` | 样例完整配置 |
| POST | `/api/simulate` | 一次请求跑两个方案，写入 SQLite |
| GET | `/api/history` | 最近 10 次回放记录 |

`POST /api/simulate` 请求体：

```json
{
  "title": "上午集中方案",
  "base_budget_cents": 40000,
  "days": 1,
  "carryover_enabled": false,
  "units": [
    {"unit_id": "A", "name": "早间主力", "floor_cents": 8000, "weight": 1,
     "daily_cap_cents": 20000, "active_start_hour": 0, "active_end_hour": 12}
  ],
  "profile": [{"available_impressions": 2000, "price_cents": 50}],
  "pauses": [{"unit_id": "B", "requested_hour": 8, "end_hour": 12}]
}
```

`profile` 必须恰好 24 项（0..23 点）。响应 `results` 为 `[等权重, 自定义权重]`，
每天包含各单元日预算、保底/权重分配额、逐小时切片/滚入/可花/购买/支出/滚出，
以及当日汇总与全局未分配金额。
